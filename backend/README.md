# Фото сообщества, лайки и баллы — каркас

Что уже работает в приложении (вкладка «Карта», карточка места):

- **Галерея «в жизни»**: первое фото — выбранное нами (Commons/gtadb), дальше до 5 снимков Wikimedia Commons (ссылками на превью
  upload.wikimedia.org, с автором и лицензией), потом фото игроков. Листается пальцем, на весь экран — по нажатию.
- **Лайк** на каждом фото. Порядок в галерее — по лайкам: лучшее фото места первое.
- **«＋ Ваше фото»**: снять или выбрать фото → тип «с земли / ночь / дрон» → согласие автора (CC BY 4.0) → «Опубликовать».
  Фото сжимается на телефоне (1600 px + превью 360 px, EXIF удаляется). Где снято: GPS из файла, иначе геопозиция телефона;
  ≤ 300 м от места — бонус «снято на месте».
- **Баллы** (★ над картой): история и правила.

Сейчас режим `local` (`js/community-config.js`): фото, лайки и баллы хранятся только на устройстве (IndexedDB) — это рабочий каркас
и демо для записи. Общий режим — Supabase.

## Правила баллов

| Действие | Баллы | Когда начисляются (на сервере) |
|---|---|---|
| Фото места | +10 | после одобрения модератором |
| Снято на месте (≤ 300 м) | +5 | вместе с одобрением |
| Съёмка с дрона | +20 | вместе с одобрением |
| Лайк вашему фото | +1 | сразу (за свой лайк — нет; снятие лайка −1) |
| Ваше фото стало главным у места (лидер по лайкам, ≥ 5 лайков) | +50 | один раз |

Константы — `POINTS` в `js/community.js` и триггеры в `backend/supabase.sql` (держать одинаковыми).

## Как включить общий сервер (один раз, ~15 минут)

1. Создать бесплатный проект на supabase.com (регион US East — ближе к Майами/LA).
2. SQL Editor → вставить и выполнить `backend/supabase.sql` целиком.
3. Authentication → Providers → включить **Anonymous sign-ins** (аккаунт на устройство без регистрации).
4. Project Settings → API: скопировать `Project URL` и `anon public` ключ в `js/community-config.js`, `mode: 'supabase'`.
5. Назначить модератора: `update public.profiles set is_moderator = true where id = '<uuid>';`
   Одобрять фото: `update public.photos set status = 'approved' where id = '…';` (позже — простая админ-страница).
6. Поднять `VERSION` в `sw.js` и выложить.

Код режима `supabase` в `js/community.js` написан без SDK (REST), но на живом сервере ещё не проверялся — проверить на шаге 4.

## Защита от накруток и права

- Баллы пишет только база (триггеры `security definer`); клиент не может вставить запись в `points_ledger`.
- Фото видно всем только после модерации; лайкать можно только одобренные; один лайк на пользователя и фото.
- Лимит 20 фото в сутки на пользователя; размер ≤ 5 МБ, только JPEG; путь в хранилище — папка пользователя.
- «Снято на месте» присылает клиент — поэтому бонус только вместе с ручным одобрением. Следующий шаг: сравнивать
  координаты из EXIF (до сжатия) и геопозицию в момент съёмки, флаг подозрительных расхождений для модератора.
- Анонимные аккаунты могут грузить и лайкать; обмен баллов на награды (в будущем) — только после подтверждения аккаунта
  (почта / Apple / Google) и проверки уникальности устройства.
- Лицензия фото игроков — CC BY 4.0 (подпись автора в карточке). Людей в кадре и номера машин — размывать на модерации;
  муралы Wynwood и т. п. — по праву художника (не главным фото без разрешения).
- App Store: пользовательский контент требует жалобы на фото и блокировки автора (правило 1.2) — добавить кнопку «Пожаловаться»
  до публикации в сторе; геопозиция — с объяснением зачем (5.1.5).

## Идеи монетизации поверх этого каркаса (на будущее)

- Баллы → бонусы в приложении (Pro на неделю, эксклюзивные значки/рамки), розыгрыши, мерч.
- Задания-«охоты» по районам (собери 5 мест South Beach) — спонсорские маршруты с отелями/турами (партнёрские комиссии).
- Платные заказы на съёмку: «нужно фото с дрона этого места» → награда автору лучшего снимка.
- Лицензирование лучших фото (с согласия авторов) для гайдов и медиа, доля автору.
